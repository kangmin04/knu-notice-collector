## 1. 기반 작업
- [x] `@xenova/transformers` 의존성 + `test` 스크립트 추가 — 기계적 작업, `package.json` 수정만으로 끝남 (계획 §2, §7)
- [x] `src/relevance/similarity.js`의 `cosineSimilarity` 구현 + 테스트 통과 — 순수 수학 구현, 사람이 직접 짜서 배우는 파트 (계획 §2, §7)

## 2. 임베딩 파이프라인
- [x] `src/relevance/embed.js` — transformers.js pipeline 래핑, 모듈 singleton으로 lazy-load — 라이브러리 API를 따라가는 작업이라 상대적으로 기계적 (계획 §2)
- [x] `src/relevance/index.js` — `scoreTitle(title)`(margin 계산)과 `isRelevant(title)`(threshold 비교 + fail-open) 완성 — embed/similarity/prototypes를 엮는 조립 작업, threshold 처리 방식(예외 시 fail-open)은 설계 판단이 이미 정해져 있으니 그대로 구현 (계획 §1, §2, §3)

## 3. 라벨 데이터 확보 — ⏱ 시간이 걸리는 수작업 구간
- [x] `scripts/export-labels-from-notion.js` 작성 및 실행 — 노션 "새 글 피드" DB 조회해 `data/labels.json` 스켈레톤 생성. 계획 당시 가정(100건 이하)과 달리 실제로는 451건이 쌓여 있어, 최근 것부터 400건으로 범위를 좁혀 가져오는 것으로 조정함(`RECENT_LIMIT`). `docs/adr/0007` 참고 (계획 §5)
- [x] **`data/labels.json`의 각 항목을 `true`/`false`로 직접 라벨링** — 400건(관련 있음 111 / 무관 289) 완료. `npm run label`(`scripts/label-cli.js`)로 진행함 (계획 §5)
- [x] `scripts/tune-threshold.js` 작성 및 실행 — precision/recall/F1 테이블 출력. 200건 시점 추천값(threshold 0.1525)이 400건으로 늘리자 0.0504로 크게 바뀌어, 초기 추천이 표본 부족으로 불안정했다는 게 확인됨 — **최종 `RELEVANCE_THRESHOLD=0.0504`로 결정**(precision 44.5%, recall 44.1%) (계획 §5)
