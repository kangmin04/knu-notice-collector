# 0005 — 최초실행 판단을 사이트 단위로 변경

## 상태
승인됨

## 맥락
`src/store.js`의 `loadStore()`는 `data/seen.json` **파일이 존재하는지**만으로 `isFirstRun`을 전역으로 결정한다(`ENOENT`면 `true`, 있으면 `false`). `src/collect.js`는 이 전역 플래그가 `true`일 때만 "현재 글 전체를 기준선으로 저장하고 노션에는 안 쓴다"는 안전장치를 적용한다.

이 파일은 기존 9개 사이트를 수집하면서 이미 생성되어 있다. 따라서 `sites.js`에 새 사이트를 추가하면:
1. `store[newSite.id]`가 없으므로 `seenIds`가 빈 `Set`이 된다.
2. 전역 `isFirstRun`은 이미 `false`이므로 "기준선만 저장" 분기를 타지 않는다.
3. 그 사이트에서 파싱된 **현재 게시글 전부**가 `newItems`로 취급되어 그대로 노션에 추가된다.

신규 사이트를 최소 18곳 추가할 계획이므로, 이 버그를 방치하면 사이트당 수십 건 × 18곳 규모의 스팸이 "새 글 피드" DB에 한꺼번에 쏟아진다.

## 결정
최초실행 판단을 **사이트 단위**로 바꾼다: `site.id`가 `store`에 없으면(즉 이 사이트를 한 번도 수집한 적이 없으면) 그 사이트만 현재 글 전체를 기준선으로 저장하고 노션에는 쓰지 않는다. 전역 `isFirstRun`(파일 자체가 없는 진짜 최초 부트스트랩)은 하위 호환을 위해 남겨두되, 사이트 단위 판단이 상위 개념이 되도록 로직을 재구성한다.

## 결과
- 기존 9개 사이트는 이미 `store`에 있으므로 동작 변화가 없다.
- 신규 사이트는 추가된 첫 실행에서 자동으로 "기준선 초기화만 하고 노션에는 안 씀" 상태가 되어, 별도의 수동 개입 없이 안전하게 추가할 수 있다.
- 이 변경은 Phase 1([[../PRD]] 참고)에서 다른 어떤 파서/의존성 변경보다 먼저 적용한다 — 이후 모든 신규 사이트 추가 작업의 전제 조건이다.
