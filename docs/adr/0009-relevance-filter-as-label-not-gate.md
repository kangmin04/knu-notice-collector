# 0009 — 관련성 필터를 "게이트"에서 "라벨"로 전환

## 상태

승인됨

## 맥락

`docs/adr/0008`에서 도입한 임베딩 기반 관련성 필터는 무관 판정된 글을 아예 노션에 올리지 않고 `[SKIP]` 로그만 남기는 방식이었다(fail-closed 게이트). 그런데 현재 threshold(F0.5 최적값 `0.0504`) 기준 precision이 44.5% 수준이라(`docs/adr/0008` 근거 참고), 실제로는 관련 있는 글 중 상당수가 조용히 걸러질 위험이 있고, 사용자 입장에서는 "혹시 놓친 공지가 있는 건 아닐까" 확인할 방법이 없었다 — 애초에 이 프로젝트의 목적(`CLAUDE.md`)이 "여러 사이트를 매번 확인해야 하는 불편함을 줄이는 것"이므로, 필터 오분류로 원본 데이터 자체가 유실되는 것은 그 목적과 충돌한다.

## 결정

`src/collect.js`에서 `isRelevant(item.title)` 판정 결과로 노션 기록 여부를 결정하지 않는다. **새 글은 관련 여부와 무관하게 전부 노션 "새 글 피드" DB에 기록**하고, 판정 결과는 새로 추가한 `IT 관련` 체크박스 속성(Notion DB 스키마에 직접 추가)에 표시만 한다. 사용자가 노션에서 체크박스로 직접 필터링/정렬해서 볼 수 있다.

`src/relevance/index.js`의 `isRelevant` 자체(임베딩 계산, threshold 비교, fail-open 정책)는 그대로 유지한다 — 로직은 동일하고, 그 결과를 "쓰지 말지"가 아니라 "무엇으로 표시할지"에만 쓰는 것으로 소비처만 바뀐 것이다.

## 근거

- **원본 데이터 유실 방지가 필터 자체보다 우선**: precision 44.5% 수준에서는 관련 있는 글이 무관으로 오분류돼 통째로 사라지는 경우가 실제로 존재한다(`docs/adr/0008` 결과 절 참고). 게이트 방식은 이 오분류를 사용자가 알아챌 방법조차 없앤다.
- **`scripts/export-labels-from-notion.js` 기반 threshold 재튜닝 파이프라인과 호환**: 이 스크립트는 애초에 노션 DB에 쌓인 글(관련/무관 섞임)을 가져와 라벨링하는 방식으로 동작해왔다(`docs/adr/0008`의 400건 라벨링도 필터 도입 *이전*에 전부 기록되던 시절 데이터였다). 모든 글을 계속 기록하면 향후 라벨 표본이 끊기지 않고 계속 쌓인다.
- **체크박스가 select/멀티셀렉트보다 적합**: `IT 관련` 여부는 이진값이고, 노션에서 체크박스는 필터/보드 뷰 그룹핑이 바로 가능해 별도 설정 없이 "관련 있는 것만 보기" 뷰를 만들 수 있다.

## 결과

- `src/notion.js`의 `addFeedItem`이 `relevant`(boolean)를 받아 `IT 관련` 체크박스 속성에 반영한다.
- `src/collect.js`는 더 이상 `!relevant`일 때 `continue`하지 않는다 — `newItems`는 전부 `addFeedItem`을 거치고, 로그는 사이트별로 "새 글 N건 노션에 추가 (IT 관련 X건 / 무관 Y건)" 형태로 바뀐다.
- 노션 "새 글 피드" DB 스키마에 `IT 관련`(checkbox) 속성을 API로 직접 추가했다(기존에 있던 `확인` 체크박스는 사용자가 수동으로 확인 표시하는 별개 용도라 재사용하지 않음).
- `RELEVANCE_THRESHOLD`/`RELEVANCE_FILTER_DISABLED` 환경변수, `scripts/tune-threshold.js` 등 threshold 튜닝 인프라는 전부 그대로 유효하다 — 값이 사용되는 곳만 "게이트 조건"에서 "체크박스 값"으로 바뀌었다.
- 향후 관련성 판정 품질(precision/recall)이 충분히 검증되면 다시 게이트 방식으로 되돌리는 것도 가능하나, 그 경우 노션에 이미 쌓인 `IT 관련` 체크박스 데이터를 라벨 삼아 재평가할 수 있다는 이점이 생긴다.
